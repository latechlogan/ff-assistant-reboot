# 001 — Walking skeleton: chopped waiver board, one week, end to end

## Job
Produce a printed waiver board for the chopped league for the current week, from a real
Sleeper pull, through the whole pipeline: config → player index → weekly projections →
local scoring → replacement level and VORP → survival-weighted rest-of-season points →
FAAB value. No freezing, no bid range, no standard league.

## Context
This is slice 1 of the build order in `docs/architecture.md`, and the first code in the
repo. The 2026 tool (`~/repos/ff-assistant`, being deleted once this one is live) proved
the math; what it lacked was a stated architecture, tests Logan trusted, and
reproducibility. Three of its hard-won corrections must survive the rewrite and are
logged in `DECISIONS.md`:

- A bye week arrives with **no `gp` field and no `game_id`**, stats holding only
  `adp_dd_ppr` — not `gp = 0`.
- A chopped roster comes back with `settings.eliminated: 1`, `players: null`, and
  `owner_id` still set. `eliminated` is the only reliable signal.
- Sleeper permits over-roster states, so the available pool is the **observed
  complement** of live rosters' `players` + `reserve` + `taxi`, never
  `teams × rosterSize`.

Replacement level is computed over **all** players with `teams = liveTeams` (a rostered
starter still sets the bar); values are then assigned only to the available pool.

## Scope
Touches: `src/core/{config,players,scoring,rosters,survival,valuation}`,
`src/adapters/{sleeper,store,cli,obs}`, `src/core/ports.ts`, `test/fixtures/`, and the
package scaffolding (`package.json`, `tsconfig.json`, `eslint`, `prettier`,
`.dependency-cruiser.cjs`, `vitest.config.ts`).

Does NOT touch: the board artifact and freezing (ticket 002), the standard league
(003), the crawl or bid curve (004), the bid range, balance and spend pace (005).

## Done looks like
*Approved by Logan 2026-09-18. The core tests are written from these criteria by a
separate agent, before the implementation exists.*

- **AC1** — `pnpm waivers --league chopped` prints a table of available players with
  positive VORP, one row each: player, position, weighted rest-of-season points, VORP,
  value in FAAB dollars.
- **AC2** — League settings (teams, budget, roster shape, scoring, FAAB, minimum bid)
  are read from the league's own Sleeper payload. No league constant appears as a
  literal anywhere in `src/`.
- **AC3** — Fantasy points are computed locally from that league's `scoring_settings`;
  no `pts_*` field from any feed is read.
- **AC4** — A bye row (no `gp`, no `game_id`, stats holding only `adp_dd_ppr`) scores
  0.0 for that week and does not throw.
- **AC5** — A roster with `settings.eliminated: 1` is excluded from live rosters, and
  its players appear in the available pool.
- **AC6** — The available pool is the complement of the union of live rosters' players,
  reserve and taxi; a league holding more players than its roster shape allows still
  produces a correct pool size.
- **AC7** — Value over the available rows sums to the distributable share of the FAAB
  pool, asserted against that named population (not all rows, which include floor
  prices).
- **AC8** — Two consecutive runs over the same as-of files produce byte-identical
  output. No clock is read anywhere in `src/core/**`.
- **AC9** — `depcruise` fails if anything in `src/core/**` imports `node:fs`,
  `node:http`, `fetch`, or `src/adapters/**` (proved by `pnpm check`: the rule lives in
  `.dependency-cruiser.cjs` and `eslint.config.js`, and was verified by writing a
  deliberate violation — DECISIONS.md 2026-09-18).
- **AC10** — Unmatched projection rows are logged loudly at any verbosity, with counts,
  and the run says how many rows it dropped below replacement.
- **AC11** — `pnpm check` passes: format, lint, typecheck, dependency rules, tests,
  privacy scan, gitleaks (proved by `pnpm check` itself — a test asserting it would be
  the check calling itself).
- **AC12** — Tests run with no network, against scrubbed fixtures in `test/fixtures/`
  regenerated by `pnpm fixtures`; no real handle, owner ID, or league ID appears in the
  repo (proved by `pnpm check`: `pnpm privacy-scan` gates the repo, and
  `test/fixtures.test.ts` gates the fixtures).

## Boundary
- Read-only Sleeper, always. No writes, no bids.
- No invented curves: the survival weighting is the measured cadence from league
  settings, not a shape chosen because it looks right.
- Ask first on: new dependencies (v1 is Zod plus dev tooling), pricing math changes,
  anything written into `../ff-assistant-data`.
- Deliberately deferred: the board artifact, parity against the 2026 week-2 board, the
  standard league, everything bid-related.
